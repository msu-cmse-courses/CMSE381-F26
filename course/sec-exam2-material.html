    Ch 5.1.3: K-fold cross-validation
    🔗

    Objectives: Covered in this class

    • K-fold cross-validation
      🔗
      🔗
    🔗

    The idea.

    • \(K=5\) in this example
      🔗
      🔗
    • Randomly sort, split up into \(K\) subsets
      🔗
      🔗
    • If \(K=n\text{,}\) then we get LOOCV
      🔗
      🔗
    🔗
    🔗

    Mathy version.

    • Randomly split data into \(k\)-groups (folds)
      🔗
      🔗
    • Approximately equal sized. For the sake of notation, say each set has \(\ell\) points
      🔗
      🔗
    • Remove \(i\) th fold \(U_i\) and reserve for testing.
      🔗
      🔗
    • Train the model on remaining points
      🔗
      🔗
    • Calculate \(\mathrm{MSE}_i = \frac{1}{\ell} \sum_{(x_j,y_j)\in U_i}(y_j-\hat y_j)^2\)
      🔗
      🔗
    • Rinse and repeat
      🔗
      🔗
    🔗
    Return
    🔗
    \begin{equation*} \mathrm{CV}_{(k)} = \frac{1}{k}\sum_{i=1}^{k} \mathrm{MSE}_i \end{equation*}
    🔗

    Ch 5.1.4: CV bias-variance trade-off
    🔗

    Objectives: Covered in this class

    • Bias-variance tradeoff
      🔗
      🔗
    🔗

    Bias-Variance Tradeoff: Bias.

    \begin{equation*} E(y_0 - \hat{f}(x_0))^2 = \operatorname{Var}(\hat{f}(x_0)) + [\operatorname{Bias}(\hat{f}(x_0))]^2 + \operatorname{Var}(\epsilon) \end{equation*}
    🔗
    We are discussing bias in the estimation of test error rate.
    🔗
    Validation set: High bias. It overestimates test error because it uses a small subset of the data.
    🔗
    LOOCV: Gives an approximately unbiased estimate because it uses almost all the data each time ( \(n-1\) observations) for training.
    🔗
    \(k\)-fold CV: has a medium level of bias because each training set has approximately \((k-1)n/k\) observations.
    🔗
    🔗

    Bias-Variance Tradeoff: Variance.

    \begin{equation*} E(y_0 - \hat{f}(x_0))^2 = \operatorname{Var}(\hat{f}(x_0)) + [\operatorname{Bias}(\hat{f}(x_0))]^2 + \operatorname{Var}(\epsilon) \end{equation*}
    🔗
    We are discussing variance in the estimation of test error rate.
    🔗
    • Validation set has high variance:
      • The estimate of test error is highly dependent on the particular split of the data.
        🔗
        🔗
      🔗
      🔗
    • LOOCV has high variance:
      • It averages the outputs of \(n\) fitted models, each trained on almost identical observations.
        🔗
        🔗
      • The fitted models are highly correlated with each other.
        🔗
        🔗
      • The mean of highly correlated quantities has higher variance than the mean of uncorrelated quantities.
        🔗
        🔗
      🔗
      🔗
    🔗
    • \(k\)-fold CV: Medium variance.
      • The \(k\) fitted models are somewhat less correlated with each other.
        🔗
        🔗
      • Empirically, \(k=5\) or \(10\) has been shown to be a happy medium.
        🔗
        🔗
      🔗
      🔗
    🔗
    🔗

    In short: Validation vs LOOCV vs \(k\)-Fold CV.

    • We often treat the validation set as if it were the test set, even though it is not.
      🔗
      🔗
    • A true test set is an independent sample.
      🔗
      🔗
    • Cross-validation measures never provide that independent sample.
      🔗
      🔗
    🔗
    Method
    🔗
    Bias
    🔗
    Variance
    🔗
    Validation Set Approach
    🔗
    High: Consistently overestimates the true test error because of small training size.
    🔗
    High: Very sensitive to the choice of the splits.
    🔗
    \(k\)-Fold Cross-Validation
    🔗
    Medium: Uses a large proportion of the data ( \((k-1)/k\,N\) ) for training.
    🔗
    Medium: Averaging across the folds reduces the effect of the randomly obtained folds.
    🔗
    Leave-One-Out (LOOCV)
    🔗
    Low: Uses almost all ( \(N-1\) ) data points for training.
    🔗
    High: The \(N\) models are trained on nearly identical data, so the resulting models are highly correlated.
    🔗
    🔗

    Using K-Fold CV on Polynomial Linear Regression.

    Polynomial regression
    🔗
    Replace the linear model
    \begin{equation*} y_i = \beta_0 + \beta_1 x_i + \epsilon_i \end{equation*}
    with
    \begin{equation*} y_i = \beta_0 + \beta_1 x_i + \beta_2 x_i^2 + \cdots + \beta_d x_i^d + \epsilon_i \end{equation*}
    🔗
    • These models can be fit with linear regression by passing in predictors \(x_i^\ell\text{.}\)
      🔗
      🔗
    • We tend not to go higher than degree 3 or 4 because the model can become overly flexible.
      🔗
      🔗
    🔗

    Checkpoint 84.

    (a)

    If we use 10-fold cross-validation, what percentage of the data is used for training in each fold?
    🔗
    Hint.
    The model is trained on \((k-1)/k\) of the data, where \(k\) is the number of folds.
    🔗
    🔗
    Answer.
    with \(k=10\) we have \(\frac{k-1}{k} = \frac{9}{10} = 0.9\text{,}\) so 90% of the data is used for training.
    🔗
    🔗
    🔗

    (b)

    If we use 5-fold cross-validation, what percentage of the data is used for training in each fold?
    🔗
    Hint.
    The model is trained on \((k-1)/k\) of the data, where \(k\) is the number of folds.
    🔗
    🔗
    Answer.
    with \(k=5\) we have \(\frac{k-1}{k} = \frac{4}{5} = 0.8\text{,}\) so 80% of the data is used for training.
    🔗
    🔗
    🔗

    (c)

    If we use leave-one-out cross-validation, what percentage of the data is used for training in each fold?
    🔗
    Hint.
    In LOOCV, each training set has \(n-1\) observations out of \(n\) total observations.
    🔗
    🔗
    Answer.
    with \(k=n\) we have \(\frac{k-1}{k} = \frac{n-1}{n}\text{,}\) so approximately 90% of the data is used for training in each fold when \(n\) is large.
    🔗
    🔗
    🔗

    (d)

    For any two different folds in \(k\)-fold cross-validation, how many training sets are shared between them?
    🔗
    Hint.
    Splitting the data into \(k\) folds, how many of these folds do not include either of the two folds?
    🔗
    🔗
    Answer.
    For any two different folds in \(k\)-fold cross-validation, there are \((k-2)\) training sets that are shared between them.
    🔗
    🔗
    🔗

    (e)

    For any two different folds in \(k\)-fold cross-validation, what is the number of overlapping training data points?
    🔗
    Hint 1.
    For any two different folds in \(k\)-fold cross-validation, there are \((k-2)\) training sets that are shared between them.
    🔗
    🔗
    Hint 2.
    The number of samples per fold is \(N/k\text{,}\) where \(N\) is the number of samples in the training set.
    🔗
    🔗
    Hint 3.
    Knowing the number of shared training sets, and the number of samples per fold, we can calculate the number of overlapping training data points.
    🔗
    🔗
    Answer.
    The number of overlapping samples is \((k-2) \times N/k\text{,}\) where \(N\) is the number of samples in the training set.
    🔗
    🔗
    🔗

    (f)

    What is the the percentage overlap between any two different training sets in \(k\)-fold cross-validation?
    🔗
    Hint 1.
    Any two folds share \((k-2)\) training sets, which is
    \begin{equation*} (k-2)/k \end{equation*}
    of the data.
    🔗
    🔗
    Hint 2.
    The size of the training set in each fold is \((k-1)/k\) of the total data.
    🔗
    🔗
    Hint 3.
    The percentage overlap is the ratio of the number of overlapping samples to the size of the training set.
    🔗
    🔗
    Answer.
    The percentage overlap between any two different training sets in \(k\)-fold cross-validation is \(\frac{k-2}{k-1}\text{.}\)
    🔗

    CV for Classification.

    Setup: LOOCV
    🔗
    • Remove the \(i\) th point \((x_i,y_i)\) and reserve it for testing.
      🔗
    • Train the model on the remaining points.
      🔗
    • Calculate \(\operatorname{Err}_i = \mathbb{I}(y_i \ne \widehat{y}_i)\text{.}\)
      🔗
    • Rinse and repeat.
      🔗
    \(\vdots\)
    🔗
    Return the cross-validation error:
    \begin{equation*} CV_{(n)} = \frac{1}{n}\sum_{i=1}^{n}\operatorname{Err}_i \end{equation*}
    🔗
    🔗

    CV for Classification.

    Setup: \(k\)-fold
    🔗
    • Randomly split the data into \(k\) groups (folds).
      🔗
    • Make the folds approximately equal in size. For notation, suppose each fold has \(\ell\) points.
      🔗
    • Remove the \(i\) th fold \(U_i\) and reserve it for testing.
      🔗
    • Train the model on the remaining points.
      🔗
    • Calculate
      \begin{equation*} \operatorname{Err}_i = \frac{1}{\ell} \sum_{(x_j,y_j)\in U_i} \mathbb{I}(y_j \ne \widehat{y}_j) \end{equation*}
      🔗
    • Rinse and repeat.
      🔗
    Return the cross-validation error:
    \begin{equation*} CV_{(k)} = \frac{1}{k}\sum_{i=1}^{k}\operatorname{Err}_i \end{equation*}
    🔗
    🔗

    • How can you carry out these procedures by hand, given the training and cross-validation test errors for each combination of predictors?
      🔗
      🔗
    • What are the pros and cons of each feature selection method? When can or can’t you use them?
      🔗
      🔗

    🔗

    Subset selection.

    The problem of many features (p) relative to samples (n)
    🔗
    Up to now, we’ve focused on the standard linear model:
    \begin{equation*} Y = \beta_0 + \beta_1 X_1 + \cdots + \beta_p X_p + \varepsilon \end{equation*}
    and done least squares estimation.
    🔗
    Translation: minimize \(RSS = \sum_i (y_i - \hat{y}_i)^2\text{.}\)
    🔗
    Prediction accuracy
    🔗
    • If the true relationship is approximately linear, least squares estimates have low bias.
      🔗
      🔗
    • If \(n \gg p\text{,}\) least squares also has low variance.
      🔗
      🔗
    • If \(n\) is not much larger than \(p\text{,}\) estimates have high variability, which can lead to overfitting and poor predictions.
      🔗
      🔗
    • If \(n < p\text{,}\) there is no unique solution, so least squares cannot be used.
      🔗
      🔗
    • Goal for the next slide: shrink or constrain the number of variables to improve accuracy.
      🔗
      🔗
    🔗
    Model interpretability
    🔗
    • Often, many included variables are not associated with the response.
      🔗
      🔗
    • Including them leads to unnecessary complexity in the model.
      🔗
      🔗
    • Idea: set these coefficients to zero or close to zero.
      🔗
      🔗
    • Goal for the next slide: use automatic feature selection (variable selection) to remove unnecessary variables.
      🔗
      🔗
    🔗
    🔗

    • The idea is to fit the model \(2^p\) times, score each model, and choose the one with the best score.
      🔗
      🔗
    • The subsets are grouped into tiers by the number of variables \(k\) selected from the \(p\) available variables.
      🔗
      🔗
    • Models with the same \(k\) can be compared without considering the order of the variables.
      🔗
      🔗
    • Each tier has \(\binom{p}{k}\) combinations, where
      \begin{equation*} \binom{p}{k} = \dfrac{p!}{k!(p-k)!}\text{.} \end{equation*}
      🔗
      🔗
    🔗
    🔗

    One way of breaking this up.

    Algorithm 86 Best subset selection.

    1. Let \(\mathcal{M}_0\) denote the null model, which contains no predictors. This model simply predicts the sample mean for each observation.
      🔗
      🔗
    2. For \(k = 1, 2, \ldots, p\text{:}\)
      1. Fit all \(\binom{p}{k}\) models that contain exactly \(k\) predictors.
        🔗
        🔗
      2. Pick the best among these \(\binom{p}{k}\) models, and call it \(\mathcal{M}_k\text{.}\) Here, best is defined as having the smallest RSS, or equivalently, the largest \(R^2\text{.}\)
        🔗
        🔗
      🔗
      🔗
    3. Select a single best model from among \(\mathcal{M}_0, \ldots, \mathcal{M}_p\) using cross-validated prediction error, \(C_p\) (AIC), BIC, or adjusted \(R^2\text{.}\)
      🔗
      🔗
    🔗
    🔗
    • Part 2b chooses the model with the lowest training score; Part 3 then chooses the model with the lowest testing score.
      🔗
      🔗
    • Step 2 is computationally infeasible for large \(p\text{.}\)
      🔗
      🔗
    🔗

    Forward Stepwise Selection.

    Algorithm 89 Forward stepwise selection.

    1. Let \(\mathcal{M}_0\) denote the null model, which contains no predictors.
      🔗
      🔗
    2. For \(k = 0, \dots, p - 1\text{:}\)
      🔗
      1. Consider all \(p - k\) models that augment the predictors in \(\mathcal{M}_k\) with one additional predictor.
        🔗
        🔗
      2. Choose the best among these \(p - k\) models, and call it \(\mathcal{M}_{k+1}\text{.}\) Here best is defined as having smallest RSS or highest \(R^2\text{.}\)
        🔗
        🔗
      🔗
      🔗
    3. Select a single best model from among \(\mathcal{M}_0, \dots, \mathcal{M}_p\) using cross-validated prediction error, \(C_p\) (AIC), BIC, or adjusted \(R^2\text{.}\)

    Pros and Cons of Forward Stepwise.

    Pros:
    • Computationally cheaper.
      🔗
      🔗
    • The number of models fit is
      \begin{equation*} 1 + \sum_{k=0}^{p-1}(p-k) = 1 + \frac{p(p+1)}{2} \end{equation*}
      which is much less than \(2^p\text{.}\)
      🔗
      🔗
    🔗
    Cons:
    • It is not guaranteed to find the best model.
      🔗
      🔗
    • For example, if the best one-variable model uses \(X_1\text{,}\) but the best two-variable model uses \(X_2\) and \(X_3\text{,}\) forward selection will not find it.
      🔗
      🔗
    • If \(n < p\text{,}\) it can only construct models \(\mathcal{M}_0\) through \(\mathcal{M}_{n-1}\text{.}\)
      🔗
      🔗
    🔗
    🔗

    Backward Stepwise Selection.

    Algorithm 92 Backward stepwise selection.

    1. Let \(\mathcal{M}_p\) denote the full model, which contains all \(p\) predictors.
      🔗
      🔗
    2. For \(k = p, p - 1, \dots, 1\text{:}\)
      🔗
      1. Consider all \(k\) models that contain all but one of the predictors in \(\mathcal{M}_k\text{,}\) for a total of \(k - 1\) predictors.
        🔗
        🔗
      2. Choose the best among these \(k\) models, and call it \(\mathcal{M}_{k-1}\text{.}\) Here best is defined as having smallest RSS or highest \(R^2\text{.}\)
        🔗
        🔗
      🔗
      🔗
    3. Select a single best model from among \(\mathcal{M}_0, \dots, \mathcal{M}_p\) using cross-validated prediction error, \(C_p\) (AIC), BIC, or adjusted \(R^2\text{.}\)
      🔗
      🔗
    🔗

    Ridge regression.

    Before:
    🔗
    \begin{equation*} RSS = \sum_{i=1}^{n} \left(y_i-\beta_0-\sum_{j=1}^{p}\beta_j x_{ij}\right)^2 \end{equation*}
    🔗
    After:
    🔗
    \begin{equation*} \sum_{i=1}^{n} \left(y_i-\beta_0-\sum_{j=1}^{p}\beta_j x_{ij}\right)^2 +\lambda\sum_{j=1}^{p}\beta_j^2 = RSS+\lambda\sum_{j=1}^{p}\beta_j^2 \end{equation*}
    🔗
    • \(\lambda \geq 0\) is a tuning parameter to determine separately.
      🔗
      🔗
    • The second term is called the shrinkage penalty.
      🔗
      🔗
    • \(\lambda=0\) gives the least squares estimate.
      🔗
      🔗
    • This is our first encounter with regularization, the \(l_2\) norm, and the general \(l_p\) norm.
      🔗
      🔗
    • Regularization constrains the model, reducing its flexibility.
      🔗
      🔗
    🔗
    • As \(\lambda\to\infty\text{,}\) the shrinkage penalty has an increasing impact, and the ridge regression coefficients approach zero.
      🔗
      🔗
    • The penalty is not applied to the intercept.
      🔗
      🔗
    • Denote the ridge regression coefficient estimates by \(\hat{\boldsymbol{\beta}}_{\lambda}^{R} =(\hat{\beta}_{1,\lambda}^{R},\ldots,\hat{\beta}_{p,\lambda}^{R})\text{.}\)
      🔗
      🔗
    🔗
    🔗

    Example from the Credit data.

    \begin{equation*} RSS + \lambda \sum_{j=1}^{p}\beta_j^2 \end{equation*}
    🔗
    • At the left end of the x-axis, \(\lambda \approx 0\text{.}\)
      🔗
      🔗
    • Each line represents the predicted coefficient value for a single variable.
      🔗
      🔗
    • As \(\lambda\) increases, all coefficients approach zero, essentially giving the null model at the right end.
      🔗
      🔗
    🔗
    🔗

    Same Setting, Different Plot.

    \begin{equation*} RSS + \lambda \sum_{j=1}^{p}\beta_j^2 \qquad \|\boldsymbol{\beta}\|_2 = \sqrt{\sum_{j=1}^{p}\beta_j^2} \end{equation*}
    🔗
    • The vector \(\hat{\boldsymbol{\beta}}\) contains the least squares coefficient estimates.
      🔗
      🔗
    • The norm \(\|\cdot\|_2\) measures the distance from zero.
      🔗
      🔗
    • The ratio \(\|\hat{\boldsymbol{\beta}}_\lambda^R\|_2/\|\hat{\boldsymbol{\beta}}\|_2\) ranges from \(1\) when \(\lambda=0\) down to \(0\) as regularization increases.
      🔗
      🔗
    • This ratio measures the amount by which the coefficient estimates have been shrunk.
      🔗
      🔗
    • The ratio makes shrinkage more comparable across different regularization methods.
      🔗
      🔗
    • The left side is less flexible; the right side is more flexible.
      🔗
      🔗
    🔗
    🔗

    Scale equivariance (or lack thereof).

    Scale equivariant:
    🔗
    Multiplying a variable by \(c\text{,}\) giving \(cX_i\text{,}\) returns a coefficient multiplied by \(1/c\text{,}\) giving \(\beta_i/c\text{.}\)
    🔗
    • Example: income variable.
      🔗
      🔗
    • Least squares is scale equivariant.
      🔗
      🔗
    • Ridge regression is not scale equivariant.
      🔗
      🔗
    • \(X_j\hat{\beta}_{j,\lambda}^{R}\) depends not only on \(\lambda\) but also on the values of the other predictors.
      🔗
      🔗
    🔗
    🔗

    Solution: Standardize predictors.

    \begin{equation*} \widetilde{x}_{ij} = \frac{x_{ij}}{ \sqrt{\frac{1}{n}\sum_{i=1}^{n}(x_{ij}-\overline{x}_j)^2} } \end{equation*}
    🔗
    • The denominator is the estimated standard deviation of the \(j\)th predictor.
      🔗
      🔗
    • Standardized predictors will all have a standard deviation of one.
      🔗
      🔗
    • Previous figures showed standardized ridge regression coefficients on the \(y\)-axis.
      🔗
      🔗
    🔗
    🔗

    Using Cross-Validation to Find \(\lambda\).

    • Choose a grid of \(\lambda\) values.
      🔗
      🔗
    • Compute the ( \(k\)-fold) cross-validation error for each value of \(\lambda\text{.}\)
      🔗
      🔗
    • Select the tuning parameter value \(\lambda\) for which the cross-validation error is smallest.
      🔗
      🔗
    • Refit the model using all available observations and the selected value of the tuning parameter.
      🔗
      🔗
    🔗
    🔗

      🔗

      🔗
      🔗
    • The dip is not very pronounced, so a wide range of values would give a very similar error.
      🔗
      🔗
    • In a case like this, we might simply use the least squares solution.

    🔗

      🔗
      🔗

      🔗

    Lasso: Least Absolute Shrinkage and Selection Operator.

    Same goal as before:
    • Fit model using all \(p\) predictors.
      🔗
      🔗

      🔗
      🔗

    Note 96.

    Ridge shrinks coefficients but does not eliminate them, which is what we actually want.
    🔗
    🔗
    \begin{equation*} Y = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \beta_3 X_3 + \beta_4 X_4 \end{equation*}
    🔗

    The lasso.

    Least Squares:
    🔗
    \begin{equation*} RSS = \sum_{i=1}^{n} \left(y_i - \beta_0 - \sum_{j=1}^{p} \beta_j x_{ij}\right)^2 \end{equation*}
    🔗
    Ridge:
    🔗
    \begin{equation*} \sum_{i=1}^{n} \left(y_i - \beta_0 - \sum_{j=1}^{p} \beta_j x_{ij}\right)^2 + \lambda \sum_{j=1}^{p} \beta_j^2 = RSS + \lambda \sum_{j=1}^{p} \beta_j^2 \end{equation*}
    🔗
    The Lasso:
    🔗
    \begin{equation*} \sum_{i=1}^{n} \left(y_i - \beta_0 - \sum_{j=1}^{p} \beta_j x_{ij}\right)^2 + \lambda \sum_{j=1}^{p} |\beta_j| = RSS + \lambda \sum_{j=1}^{p} |\beta_j| \end{equation*}
    🔗
    • \(\ell_1\) penalty instead of \(\ell_2\) penalty
      🔗
      🔗
    • \(\ell_1\) norm: \(\|\beta\|_1 = \sum |\beta_j|\)
      🔗
      🔗
    • \(\ell_2\) norm: \(\|\beta\|_2 = (\sum \beta_j^2)^{\frac{1}{2}}\)
      🔗
      🔗
    • \(\ell_p\) norm: \(\|\beta\|_p = (\sum |\beta_j|^p)^{1/p}\)
      🔗
      🔗
    • \(\ell_\infty\) norm: \(\|\beta\|_\infty = \max\{|\beta_i|\}\)
      🔗
      🔗
    🔗

    Subsets with lasso.

    \begin{equation*} \sum_{i=1}^{n} \left(y_i - \beta_0 - \sum_{j=1}^{p} \beta_j x_{ij}\right)^2 + \lambda \sum_{j=1}^{p} |\beta_j| = RSS + \lambda \sum_{j=1}^{p} |\beta_j| \end{equation*}
    🔗
    • The result of the \(\ell_1\) penalty is that it forces some coefficients to be exactly 0.
      🔗
      🔗
    • This can be interpreted as something like subset selection, but it is called variable selection.
      🔗
      🔗
    • The result is sparse models, which use only a subset of variables.
      🔗
      🔗
    • Selecting a good \(\lambda\) is critical.
      🔗
      🔗
    🔗
    🔗

    Why can lasso select variables while ridge cannot?

    Alternative formulation of lasso and ridge regression
    🔗
    \begin{equation*} \min_{\beta} \sum (y_i - \hat{y}_i)^2 \quad \text{where} \quad \sum |\beta_j| \leq s \end{equation*}
    🔗
    \begin{equation*} \min_{\beta} \sum (y_i - \hat{y}_i)^2 \quad \text{where} \quad \sum |\beta_j|^2 \leq s \end{equation*}
    🔗
    
    \(\hat{\beta}\) is the least squares solution. Each of the ellipses represents parameter combinations that yield a constant value of the sum of squared residuals. The blue region is the \(p\)-norm ball: diamond for \(p=1\) and circle for \(p=2\text{.}\) The parameter estimates that minimize the objective function are at the point where a contour first intersects the boundary of the \(p\)-norm ball.
    🔗
    • The ridge constraint region is circular, so the contours of the least squares error function are more likely to intersect the constraint region at a point where both coefficients are nonzero.
      🔗
      🔗
    • The lasso constraint region is diamond-shaped, so the contours of the least squares error function are more likely to intersect the constraint region at a corner, where one of the coefficients is zero.
      • In higher dimensions, the lasso constraint region gets more and more spiky with many corners, and many of the coefficients can simultaneously be set to zero.
        🔗
        🔗
      🔗
      🔗
    🔗

    Ridge vs Lasso.

    • Both Ridge and Lasso are used with linear models to reduce model variance, thus reducing overfitting and improving accuracy for new, unseen data.
      🔗
      🔗
    • Adding the Ridge or Lasso penalty, i.e., adding constraints or regularization, allows solving problems where \(n \lt p\text{.}\) The problem is unsolvable if the only penalty term is the RSS.
      🔗
      🔗
    🔗
    Least Squares:
    🔗
    \begin{equation*} RSS = \sum_{i=1}^{n} \left(y_i - \beta_0 - \sum_{j=1}^{p} \beta_j x_{ij}\right)^2 \end{equation*}
    🔗
    Ridge:
    🔗
    \begin{equation*} \sum_{i=1}^{n} \left(y_i - \beta_0 - \sum_{j=1}^{p} \beta_j x_{ij}\right)^2 + \lambda \sum_{j=1}^{p} \beta_j^2 = RSS + \lambda \sum_{j=1}^{p} \beta_j^2 \end{equation*}
    🔗
    The Lasso:
    🔗
    \begin{equation*} \sum_{i=1}^{n} \left(y_i - \beta_0 - \sum_{j=1}^{p} \beta_j x_{ij}\right)^2 + \lambda \sum_{j=1}^{p} |\beta_j| = RSS + \lambda \sum_{j=1}^{p} |\beta_j| \end{equation*}
